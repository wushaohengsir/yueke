## 1. 项目背景与问题定义

线下培训机构、独立教师与学员约课长期依赖微信群等口头方式：老师临时改课、学员撞时段、课时账目说不清、请假补课无凭据，纠纷频发无从查证。本项目面向这一场景实现一个轻量级在线约课平台，聚焦核心闭环：**老师开放可授时段 → 学员自助约课/请假 → 系统自动防冲突并沉淀记录**，作为业务与账目的唯一事实来源。首版不做真实资金往来模块（涉及资金结算需相应资质，已在 todos 与 About 页注明），课时以线下结算 + 课时包合同入账方式闭环演示。

## 2. 需求分析与角色划分

| 角色 | 核心用例 | 登录态 |
|---|---|---|
| 游客 | 浏览老师与可授时段 | 免登录 |
| 学员 | 自助约课、请假、查课时/历史 | 需登录 |
| 老师 | 维护时段模板、查周课表、审批请假、课后登记完成 | 需登录且通过入驻审核 |
| 管理员 | 老师审核、用户/科目管理、看板、代学员排远期课、停课 | 需登录 |

## 3. 总体设计

**技术栈**：前端 Vue 3 + Vite + TypeScript + Pinia（原生控件，红枫主题，移动端优先）；后端 Java 17 + Spring Boot 3 + MyBatis-Plus + Spring Security（JWT）；MySQL 8.0；部署 Docker Compose（nginx + springboot + mysql，公网 HTTPS 自签）。

**系统架构**：

```
浏览器（Vue3 SPA）
  │ REST /api/*（Authorization: Bearer JWT）
  ▼
nginx：静态资源 + /api 反代（443 HTTPS，80→301）
  ▼
Spring Boot 3（Controller→Service→Mapper）
  ├─ Spring Security + JwtUtil：鉴权 + 按 URL 前缀角色越权拦截 + 即时吊销
  └─ MyBatis-Plus → MySQL 8（yueke）
```

**分层约定**：后端三层、DTO/实体分离、统一返回体 `Result` + `OpStatus` 枚举；前端按 `views/components/stores/api/utils` 组织，组合式 API + TS 严格模式，日期/状态文案收敛到 `utils` 单一来源。

## 4. 数据库设计

按 1NF→BCNF 设计 15 张规范化表。要点：

- **用户与角色**：`user` 单表 + role 枚举（0游客/1学员/2老师/3管理员），与 `teacher_profile`、`student_profile` 1:1 扩展；M:N 一律 Junction 表。
- **金额与课时**：金额用分（INT）、课时用整数；余额不做派生存列，靠 `credit_log` 流水推导，可审计可对账。
- **生命周期**：`status` + 时间戳状态机，不做物理删除。
- **分课程课时**：`student_credit(student_id, subject_id)` 唯一约束，课时按课程独立记账不通用；合同签署后按课程入账。
- **特殊日期可约**：`timeslot_block` 记录停课/加开（本版实现屏蔽：整天或某时段，老师休息/请假时用）。

**核心创新——并发防冲突**：MySQL 不支持部分唯一索引，用「生成列 + 组合唯一索引」等价实现：新增 `active_flag = IF(status IN (0,1), 1, NULL)`，仅活跃预约（待确认/已确认）为 1，请假/取消/完成后自动为 NULL；唯一索引 `uk_teacher_active_slot(teacher_id, start_at, active_flag)` 把「同老师同时段至多一个活跃预约」约束下沉到数据库层，并发插入只有一条成功，应用层捕获冲突返回友好提示。

## 5. 详细设计

### 5.1 约课闭环流程
老师维护「星期→当天时段」模板（含停课屏蔽）→ 学员只见近期可约时段并提交 → 事务内插入预约并扣该课程课时、写「约课消耗」流水（依赖唯一索引防并发）→ 请假经老师审批通过转「已请假」并返还课时、驳回维持原状、已下课禁请假 → 老师课后登记完成转「已完成」→ 合同签署按课程入账并写流水。

### 5.2 可约时段模型与互斥
启用模板时自动拒绝与同日已启用模板重叠（模板互斥），杜绝 20:00–19:00 这类倒序时间（前后端双重校验，后端返回 400）；服务端下单前按启用模板二次校验时段归属，防绕过前端直连。停课记录由管理员维护，屏蔽后学生端当天可约、老师端周课表未来空档、管理员代排三处同步剔除。

### 5.3 注册与权限安全（本人在本阶段的主要编码工作）
- **注册闭环**：新增独立 `POST /api/auth/register`，学员/老师分身份注册。学员建档（含 `student_profile`，修新号无档约不了课）并自动登录；老师注册建待审档案 + 科目，**审核通过前登录门禁拒入**（待审/驳回都不发 token）。登录改为纯登录，不再"查无此号自动建档"；未注册/被禁用账号有明确提示。
- **身份真实性**：`GET /api/auth/me` 按 token 返回数据库真名，前端「我的」页进入即核对，消除缓存旧名（曾出现显示"学员小约"实为数据库"林小雨"的问题）。
- **角色越权收口（答辩后被反馈后修复）**：此前管理端多数接口只要求"已登录"未校验角色，存在用学员 token 即可读全站数据的越权。改为 SecurityConfig 按 URL 前缀集中隔离（`/api/admin/**`→ADMIN、`/api/teacher/**`→TEACHER、`/api/bookings|credits|leave|contracts`→STUDENT），JWT 过滤器把角色号映射为 Spring 角色权限，并对**每个请求校验用户仍存在且启用**（停用即时失效），token 有效期 8h；`/api/auth` 仅放行 login/register/subjects。
- **安全加固与部署**：登录防爆破（LoginGuard：连错 5 次锁 10 分钟）；CORS 收紧同源 + 本地开发源；nginx 隐藏版本、加 CSP/HSTS 等安全头、容器日志轮转；自签 HTTPS（80→301）；sshd 密钥-only 禁 root + fail2ban；**腾讯云安全组**收口为仅 22/80/443。通过自写 TC3 签名客户端调用腾讯云 OpenAPI 完成。
- **管理员重置密码**：忘记密码场景由管理员在「用户管理」重置学员/老师密码（`POST /api/admin/users/{id}/reset-password`，管理员账号拒绝被此口重置）。

### 5.4 前端设计
移动端 SPA、按角色路由分流。红枫主题（米白+枫红+青绿视觉体系、背景飘落枫叶、统一悬停交互——约课入口与其它按钮一致不做特殊化）；首页提供 `/about.html` 项目介绍（第八组 + 在线链接 + 范围说明）；日期/状态文案由 `utils/datetime`、`utils/status` 单一来源，登录态存 `sessionStorage` 支持多标签身份隔离。

## 6. 系统实现与运行问题分析

实现沿版本线推进：登录/约课 → 防冲突 → 管理端 → 课表两级重构 → 停课/代排课 → 注册闭环与姓名一致性 → Docker 公网部署 → 越权/裸奔修复与安全加固 → 管理员重置密码。全程及时提交并双源推送（GitHub + Gitee），commit 与 todos/日报/飞书日志可对账。

主要问题与解决：

| 问题 | 原因 | 解决 |
|---|---|---|
| 时段模板可存 20:00–19:00 倒序 | 前后端校验缺失 | 前后端同时加「结束须晚于开始」，后端 BAD_TIME 返回 400，集成测试覆盖 |
| 双标签页登录串身份 | 登录态存 localStorage 全浏览器共享 | 改 sessionStorage 标签页隔离 |
| 已下课课程仍可请假/漏登记 | 状态机边界不清 | 学生端对过去课时禁请假；老师端"下课超 20 分钟未登记"自动提醒 |
| 管理员代排远期的课与老师可约不一致 | 缺少统一时段口径 | 复用启用模板生成时段，管理员停课/模板同时约束排课 |
| 学员「我的」页显示旧缓存名 | 前端使用过期本地缓存 | 后端加 `/me`，进入页面按 token 核对数据库真名 |
| 用学员 token 可读管理端数据（越权裸奔） | 管理接口缺角色校验、后端 8080 直发公网 | 安全配置集中角色隔离 + JWT 即时校验用户状态 + 8080 不再对外；安全组收口 |
| push 被队友新提交挡住 | 本地落后远端 | fetch 确认无冲突后 rebase 合入再推送，不强推覆盖 |

## 8. 主要创新点

1. **无部分索引的并发防冲突**：生成列 + 组合唯一索引把「活跃预约唯一」约束提升到数据库层，从机制上根除并发双占。
2. **分课程课时账本 + 全量流水**：课时按课程独立，余额由 `credit_log` 推导而非直接存列，全链路可审计。
3. **"模板互斥 + 服务端二次校验 + 停课屏蔽"的可约时段模型**：唯一可约入口 + 重叠停用 + 代排同步约束，堵住跨周歧义与绕过直连。
4. **纵深安全收口**：按 URL 前缀集中角色隔离 + 每请求用户状态校验（即时吊销）+ 登录防爆破 + CORS/安全头 + HTTPS + 云安全组最小暴露，安全测试用例沉淀。
5. **真实数据口径**：删除 mock，用户展示一律以数据库为准（`/me` 核对真名），避免演示与后端对不上。
